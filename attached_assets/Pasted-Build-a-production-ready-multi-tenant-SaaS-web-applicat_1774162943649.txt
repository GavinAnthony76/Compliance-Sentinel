Build a production-ready, multi-tenant SaaS web application for lawn care companies. The platform must be designed so that many different lawn care businesses can subscribe to and use the same app from one codebase and one deployment. This is a SaaS product, not a single-company internal app.

Project Goal:
Create a polished, modern, mobile-friendly lawn care business platform where local lawn companies can sign up, subscribe to a plan, manage bookings, customers, services, invoices, reminders, and recurring jobs. The app must support multiple separate lawn companies with full tenant isolation. It must also include a super-admin dashboard for platform ownership and management.

Core Business Model:
- SaaS platform for multiple lawn care businesses
- Three subscription tiers:
  1. Starter
  2. Growth
  3. Pro
- Monthly billing through Stripe
- Optional free trial support
- Upgrade/downgrade support
- One centralized platform admin dashboard for platform owner
- Each company gets its own isolated account and data
- Each company gets its own public booking page

Tech Requirements:
- Use a modern full-stack JavaScript/TypeScript stack
- Frontend: React + Vite + TypeScript
- UI: Tailwind CSS + clean reusable component structure
- Backend: Node.js + Express or a full-stack approach that works cleanly in Replit
- Database: PostgreSQL
- ORM: Drizzle ORM preferred
- Auth: secure email/password auth with session or JWT handling
- Billing: Stripe subscriptions
- Notifications: Twilio for SMS architecture hooks, but if credentials are not present, use mock mode with clean abstraction
- Email abstraction: create a notification/email service that can later connect to Resend, SendGrid, or Postmark
- Deployment-ready for Replit
- Environment variable support throughout
- Clean architecture and scalability from day one

Critical Architecture Requirement: Multi-Tenant SaaS
This must be a true multi-tenant SaaS. Do NOT build separate apps per company.

Each lawn company should be represented as a tenant/company/account. All important data must be scoped by tenant_id or company_id, including:
- users
- customers
- services
- appointments/jobs
- recurring service plans
- invoices
- payments
- reminders
- estimates
- routes
- settings
- reviews/review requests
- automation rules
- subscription/account status

All database queries must be tenant-aware.
Every protected route must enforce tenant access.
No company should ever be able to see another company’s data.

2. Platform admin users

- owner
- admin
- staff

Role expectations:
- owner: full company access including billing/settings

- staff: limited operational access to assigned jobs/customers/calendar

Platform admin:
- separate protected admin login
- platform-wide visibility and controls
- must not be tied to one tenant/company
